# XMediatorLevelPlayMolocoAdapterCompatibility (X3M compatibility package)

Unofficial Swift Package Manager package published by X3M so XMediator apps can
use the LevelPlay Moloco adapter together with Google's
`googleads-mobile-ios-mediation-moloco` adapter.
**Not affiliated with or endorsed by Unity Technologies / ironSource.**

## Usage

Add this repository (`https://github.com/x3mads/xmediator-levelplay-moloco-swift-package.git`) and select the `LevelPlayMolocoAdapter` product.
Version `5.20.0` of this package corresponds to LevelPlay adapter
`5.20.0` (<https://github.com/ironsource-mobile/LevelPlay-Moloco-Adapter-Swift-Package.git>). Do not also add the official LevelPlay
Moloco adapter package: both contain the same adapter binary.

## Why this package exists, and why it is built this way

Google's adapter package declares a target named `MolocoAdapter`. So does
the official LevelPlay adapter package. SwiftPM requires target names to be
unique across a package graph, so a project cannot contain both.

The correct fix is SwiftPM module aliasing, and earlier versions of this package
used it: they depended on the official LevelPlay package and renamed its module
with `moduleAliases`. That works when everything is resolved under one root
`Package.swift`. It does **not** work reliably when the packages are added
directly to an Xcode project ("Add Package Dependencies"). SwiftPM applies the
aliases of only one root package, chosen in a hash-dependent order, so builds
fail at random with "multiple packages ... declare targets with a conflicting
name". This is a SwiftPM bug, fixed upstream in
https://github.com/swiftlang/swift-package-manager/pull/10630. At the time of
writing, that fix is not in any released Xcode.

As a deliberate workaround, this package no longer depends on the official
LevelPlay adapter package. Its `Package.swift` is generated by X3M from the
official manifest of the same version. It declares the same dependencies (the
same exact Moloco SDK version and the same LevelPlay SDK version range)
and the same adapter binary (the same official download URL and checksum).
Only the target names are changed (`LevelPlayMolocoAdapterTarget`, `LevelPlayMolocoAdapterSDK`),
so nothing clashes and no module aliasing is needed. We plan to return to the
aliasing approach once a fixed SwiftPM ships in Xcode, or once the official
package renames its target.

Some tags published before this change still use the aliasing approach and are
left unchanged.
